# Initialization

`agenthawk init` creates a deterministic repository policy and, optionally, one advisory coding-agent instruction file. It performs no network, Git, package-manager, provider, package-code, or lifecycle-script operation.

```bash
agenthawk init
agenthawk init --integration codex
agenthawk init --integration claude --format json
agenthawk init --integration cursor
agenthawk init --integration generic
```

The default integration is `none`, which creates only `.agenthawk.yml`. Other fixed targets are `AGENTS.md`, `CLAUDE.md`, `.cursor/rules/agenthawk.mdc`, and `AGENT-INSTRUCTIONS.md`. The current working directory is treated as the intended repository root; init does not search for or prove a Git root and accepts no arbitrary destination path.

## Collision and recovery behavior

Init never appends, merges, renames over, or rewrites a target. A safe regular file whose bytes exactly match the release-pinned generated asset is reported as `unchanged`; this is idempotency evidence, not proof that AgentHawk created or owns the file. Any different, linked, non-regular, unreadable, unstable, case-colliding, or unsafe target stops initialization.

Generated bytes are compiled into the published CLI and verified against the reviewed repository templates during the package gate. Publication uses an exclusive lock, complete files in a root-local staging directory, no-replace hard links, and identity checks. A cross-device or hard-link-unsupported target fails closed. Ordinary failures roll back only invocation-owned file identities and remove only invocation-created empty directories. Production cleanup is never recursive.

Portable filesystem APIs cannot provide a fully atomic multi-file transaction or eliminate a malicious same-user race between path checks. A process or host crash, or a filesystem that cannot return a newly created identity, can leave `.agenthawk-init.lock`, a `.agenthawk-init-*` staging directory, an empty or partial fixed target, or empty `.cursor` directories. Confirm that no init process is active, inspect only those documented generated names, and remove only the stale lock, staging material, or incomplete generated target before retrying. Existing project instructions must be merged manually; init intentionally refuses to modify them.

Exclusive creation and hard-link no-replace behavior may not be reliable or available on every network filesystem. Windows UNC roots are rejected in this version. POSIX modes are best-effort and do not claim Windows ACL hardening.

## Policy discovery

Without `--policy`, `check` and `scan` load the canonical optional `.agenthawk.yml` from the evaluated repository root through the same bounded production reader. Missing policy uses schema defaults; malformed, unsafe, or unreadable policy fails closed. An explicit `--policy <path>` always takes precedence.

## Exit behavior

- `0`: every expected target was created or already matched exactly.
- `2`: invalid options, a collision, lock, unsafe path, or unsupported precondition prevented initialization.
- `4`: an unexpected write or verification failure occurred, or cleanup could not be confirmed.

Init never uses exit `1` or `3`. JSON output uses the strict `initReportSchema` on success and the shared bounded error envelope on failure. Reports contain only fixed target identifiers and never include the absolute repository path, existing contents, temporary names, environment values, or raw operating-system errors.
